# قرارات نقل الإعدادات وأتمتة الإصدارات

هذا سجل قرارات خطتي 13 أكتوبر 2026، بالترتيب الذي اتُّخذت به، مع كلفة القرار إذا اتضح خطؤه. لا يستبدل أدلة الاختبارات أو يدّعي وجود نتائج يدوية لم يسجلها المستخدم.

1. استُخدمت واجهة داخلية لقراءة Cloudflare عبر SELECT لاختبار التحقق من الملكية وفك بيانات الربط الحقيقيين؛ اختبار فشل الخدمة الثانية عند تصدير الجميع انتقل إلى مهمة عمليات التصدير. الكلفة: صيانة واجهة داخلية إضافية.
2. يُقبل تقدم إصدار الخدمة إذا بقيت هويتها ومواردها ومفاتيحها مطابقة، مع رفض تعارض العنوان أو الحساب أو قاعدة البيانات أو المخزن أو النطاق أو المفتاح؛ واستُخدم منسق UTC صغير مختبر لتجنب اعتماد إضافي. الكلفة: إضافة أي عنصر هوية جديد مستقبلًا إلى المقارنة، وصيانة المنسق.
3. تُطابق روابط DB وMEDIA في Worker مع الملف قبل إرسال مفتاح الجهاز، بالإضافة إلى علامات الملكية. الكلفة: رفض خدمة غير مضبوطة حتى يُصلح ربط مواردها.
4. يُعزل المثبت الجديد وتوقيعه قبل تغليفهما، لأن مجلد NSIS يحتوي حزمًا أقدم. الكلفة: يتوقف البناء عند الغموض بدل اختيار ملف قديم.
5. نُقل مساعد المشغّل خارج src/bin لأن Tauri كان يكتشفه كتطبيق إضافي؛ يبقى تابعًا لأداة setup فقط. الكلفة: صيانة مسار الوحدة الجديد عند تعديل أداة المشغّل.
6. فُصل محلل ENV العام عن قائمة مفاتيح الإصدار المسموح بها، وقُيد مخزن الاختبار ببادئته المعروفة؛ وتُحسب المساحة المتبقية من الجرد الفعلي بعد الحذف المؤكد. الكلفة: إعداد اختبار غير مطابق يُرفض، وقد تظهر المساحة غير متاحة إذا تعذر تأكيد الجرد، بدل عرض قيمة مخمنة.
7. يحمل اسم مرشح القبول المصدر والبصمة حتى لا يُحجز رابط الإصدار المستقر مبكرًا. الكلفة: التحقق من تطابق الحزمة والتوقيع عند توفير اسم التنزيل المستقر.
8. نُفذت الأجزاء المستقلة من الأرشفة أثناء انتظار قبول Windows، دون إغلاق القبول أو تفعيل الإنتاج. الكلفة: تعديل تلك الأجزاء إذا تغير عقد المهمة السابقة، مع إعادة قبول المصدر النهائي.
9. تُنشأ أوسمة الاختبار من دخول التطوير الموجود ذي صلاحية Workflow، ثم تشترط Actions وجود الوسم ومصدره الصحيحين دون رمز دائم جديد. الكلفة: يتوقف النشر إذا لم تسمح صلاحيات GitHub بهذا المسار.
10. يعمل مثبت Windows بالعربية دون اختيار لغة، بعد ثبوت أن نافذة اللغة كانت توقف التحديث غير التفاعلي. الكلفة: لا يوفر المثبت اختيار لغات أخرى.
11. بدأت المراجعة المستقلة المجملة أثناء انتظار أدلة Windows والأرشفة. الكلفة: كل إصلاح مؤثر تالٍ يحتاج اختبار فشل ثم نجاح وقبول الحزمة الجديدة؛ لا يرث دليل مصدر أقدم.
12. بقي ملفا الأسرار بنص واضح بلا كلمة مرور وفق طلب المالك. الكلفة: على المالك استبدال نسخهما إذا غيّر طريقة حفظ الأسرار مستقبلًا.
13. يعتمد الإصدار توقيع تحديثات Tauri الموجود، دون شراء شهادة ناشر Windows Authenticode. الكلفة: قد يحتاج جهاز Windows آخر إلى معالجة الثقة بالناشر وفق إعدادات أمانه.
14. بقي اعتماد المستخدم لـNVDA ومعايير التسليم اليدوية منفصلًا عن نجاح الاختبارات الآلية. الكلفة: تأخر أول إصدار مستقر حتى اعتماد المستخدم.
15. بقي وسم الإنتاج والتفعيل والتسليم النهائي بعد الدليل واعتماد المستخدم. الكلفة: تأخر تفعيل تنزيلات الإنتاج إلى اكتمال الشرطين.
16. طُلب دليل Windows وأرشفة حقيقية للمصدر النهائي، دون نسبة قبول حزمة قديمة إلى كود أحدث. الكلفة: إعادة التغليف والقبول عند تغير كود الإصدار. انتقلت الأرشفة من خاصة إلى عامة بطلب المالك اللاحق.
17. لم يُغير الفرع الافتراضي لتشغيل التنظيف الأسبوعي قبل اعتماد دمج المشروع. الكلفة: إلى حين الدمج، يعمل التنظيف بعد النشر ويمكن تشغيله يدويًا، بينما الجدول الأسبوعي ينتظر وجود Workflow على الفرع الافتراضي.
18. ينقل ملف ENV الإعدادات وربط الحسابات؛ المسودات والوسائط المحلية تُحفظ منفصلة. الكلفة: يجب الاحتفاظ بهذه الملفات المحلية عند الانتقال إلى جهاز جديد.
19. أُبقيت قرارات المثبت العربي ومكان مساعد المشغّل وأسماء المرشحات وتشغيل اختبار CI بصلاحية Medium، لوجود أدلة تشخيصية عليها. الكلفة: أي تعارض مستقبلي يوقف القبول قبل التفعيل بدل تصنيع نجاح اختباري.
20. تسجل وثائق التسليم الأدلة بعد تجميد مصدر الحزمة، دون إعادة نسبة الحزمة إلى commit الوثائق. الكلفة: تغيير كود التشغيل لاحقًا يحتاج حزمة ودليل قبول جديدين.
21. سُجل رد المالك «كل شيء تمام» يوم 15 أكتوبر اعتمادًا للنسخة المسلمة، دون طلب الاعتماد نفسه مرة أخرى أو اختراع تفاصيل اختبارات يدوية. الكلفة: إذا ضيق المالك نطاق اعتماده قبل التفعيل، يتوقف التفعيل وتبقى حدود الأدلة اليدوية معلنة.
22. يُغلق التحقق النهائي بنتائج مجموعة الاختبارات الكاملة وقبول Windows على GitHub للمصدر نفسه، مع فحص الملفات والتوقيع وروابط التنزيل محليًا بالقراءة فقط، امتثالًا لطلب المالك حصر تجارب التطبيق في GitHub. الكلفة: أي تغيير في كود التشغيل يحتاج تشغيلًا جديدًا على GitHub؛ فحص الملفات وحده لا يثبت سلوك التطبيق.

## تحسينات صغيرة مؤجلة

- عند تصدير عدة خدمات وفشل واحدة منها، لا تسمي رسالة الخطأ الخدمة المتعطلة؛ يُرفض التصدير كله بأمان.
- من المراجعة الأصلية: قد يحمل ملف AVI أو MPEG الموافق للمنصة امتداد إرسال mp4 مع بقاء البايتات وMIME صحيحين؛ لم يثبت فشل نشر بسبب ذلك.
- من المراجعة الأصلية: نفاد القرص أثناء FFmpeg بعد الفحص المسبق ينتج رسالة إصلاح وسائط عامة، مع حماية الأصل وتنظيف المخرجات الفاشلة.
- من المراجعة الأصلية: قد تتراكم الوسائط المحلية المعالجة الناجحة؛ يمنع فحص المساحة الكتابة عند النقص، بينما تنظيف الملفات غير المشار إليها يحتاج متابعة منفصلة.
