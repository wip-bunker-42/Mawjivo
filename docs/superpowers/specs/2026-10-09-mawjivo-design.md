# مواصفات Mawjivo

التاريخ: 9 أكتوبر 2026. الحالة: التصميم الحواري معتمد؛ هذه الوثيقة تنتظر مراجعة المستخدم قبل كتابة خطة التنفيذ.

## 1. الغرض ومعيار النجاح

Mawjivo برنامج شخصي للنشر المتعدد، بواجهة عربية مظلمة مبنية باستخدام Tauri. Windows هو نظام التسليم الأساسي، ثم Linux وmacOS. النجاح هو تنزيل مثبت، وتشغيل التطبيق بالحسابات الفعلية، والنشر والجدولة وإدارة النتائج والتحديثات. اكتمال الكود أو عرض واجهة تجريبية وحدهما لا يحققان التسليم.

يعمل كل مستخدم على حساباته وخدمته الخاصة في Cloudflare. لا توجد خدمة SaaS مشتركة تنشر بالنيابة عن مستخدمين آخرين. الإعداد الشخصي الأول لصاحب المشروع يستفيد من الكريدينشلز الموجودة محليًا؛ الملفات القابلة للتوزيع لا تتضمن هذه البيانات.

يلتزم التنفيذ بتقليل المكونات والطلبات، وبحدود الخطط المجانية، ومعالجة الوسائط على الكمبيوتر. يختبر المستخدم التجربة النهائية بنفسه باستخدام NVDA، بعد اجتياز فحوص البنية والكيبورد الآلية واليدوية التي يجريها المطور.

## 2. القرارات المعتمدة

- Tauri 2 وRust للتطبيق والمحرك المحلي، وReact وTypeScript وVite للواجهة.
- Cloudflare Workers لواجهة الخدمة، وD1 لسجل البيانات، وR2 للوسائط، وWorkflows لتنفيذ النشر والانتظار وإعادة المحاولة.
- Facebook وInstagram عبر Meta افتراضيًا. Threads وX وYouTube وTikTok عبر Buffer في الإعداد الحالي. يمكن تبديل Facebook وInstagram إلى Buffer عند توفر قنوات مرتبطة فيه.
- YouTube عبر Buffer للـShorts فقط؛ فيديوهات يوتيوب الطويلة خارج نطاق هذه النسخة. القص المطلوب محلي ويظهر في المراجعة.
- الجدولة في Cloudflare؛ لا تحفظ مواعيد Mawjivo المستقبلية في طابور Buffer. عند حلول الموعد ترسل الخدمة طلب نشر فوري إلى الموفر.
- رفع نسخة واحدة لكل أصل أو نتيجة معالجة مختلفة، ثم إعادة استخدام الرابط بين المنصات المناسبة.
- Healthchecks يراقب نبض الخدمة ومهمة الملخص اليومي، بالإضافة إلى تقارير Telegram من التطبيق.
- مراجعة عربية مفيدة قبل كل نشر أو جدولة، وتشمل جميع التغييرات والاستبعادات المؤثرة.

تختار خطة التنفيذ أحدث الإصدارات المستقرة المتوافقة وتثبتها في ملفات القفل. إصدار LTS مناسب للبناء أفضل من إصدار أحدث غير مستقر. تعاد مقارنة الإصدارات بالمصادر الرسمية قبل التثبيت؛ وجود أداة على الكمبيوتر لا يكفي لاعتمادها.

## 3. الوضع الذي ثبت بفحوص القراءة

المستودع `aimansour/Mawjivo` خاص، وبدأ بملف استبعاد للكريدينشلز. الملف المحلي `mawjivo.secrets.env` مستبعد من Git. لا تسجل هذه الوثيقة قيم الرموز أو معرفات الحسابات الخاصة.

- نجح مفتاحا Buffer. حساب أول يحتوي Threads وYouTube، والثاني TikTok وX. القنوات متصلة وغير مقفلة، وبها صلاحيات إدارة النشر.
- نجح رمز Cloudflare من نوع رمز الحساب، والوصول إلى الحساب ونطاق `aimansour.com`. لا توجد وقت الفحص Workers أو قواعد D1 أو حاويات R2 في الحساب المتصل.
- نجحت قراءة صفحة Facebook وحساب Instagram، وتأكد الارتباط بينهما. صلاحيات نشر الصفحة وInstagram الأساسية ممنوحة. صلاحية `publish_video` في رمز المستخدم تظهر منتهية؛ لا يعتبر نشر فيديو Meta جاهزًا قبل اختبار صلاحيات المسار المطلوب وحسم أثر هذه الحالة.
- نجح فحص بوت Telegram.
- نجحت قراءة فحوص وتكاملات Healthchecks. المشروع المتصل لا يحتوي فحوصًا، والتكامل الموجود بريد إلكتروني. تنبيه Telegram المستقل من Healthchecks يحتاج تجهيز قناة مناسبة والتحقق منها.

هذه فحوص اتصال وقراءة، وليست دليلًا على نجاح النشر الحقيقي أو تجهيز البنية. يجب تحديث حالة الجاهزية بعد التنفيذ والاختبار.

## 4. حدود المكونات

| المكون | مسؤوليته | واجهته واعتماداته |
| --- | --- | --- |
| واجهة التطبيق | المسودات، الاختيار، المراجعة، عرض النتائج والإعدادات | محرك Rust وخدمة Cloudflare؛ عناصر HTML أصلية |
| محرك Rust | الملفات، فحص الوسائط ومعالجتها، الرفع القابل للاستكمال، خزنة النظام، النوافذ والتحديث | FFmpeg/FFprobe وأوامر Tauri محدودة الصلاحيات |
| قواعد المنشور المشتركة | حساب الحدود والقص، التخطيط للمراجعة، تطابق المحتوى المؤكد | TypeScript مشترك بين الواجهة وWorker، وقواعد منصات بإصدار محدد |
| Worker | التوثيق، الإعداد، المساحات، خطط النشر، الوسائط والنتائج | D1 وR2 وWorkflows وأسرار الخدمة |
| Workflows | تنفيذ المنشور عند موعده، خطوات الموفر، متابعة النتيجة | سجل D1 وموصلات Meta وBuffer؛ مراجع ملفات R2 |
| المراقبة والتقارير | نبضات Healthchecks، مراقبة التأخر، Telegram والملخص اليومي | سجل المنشورات وحالة المهام؛ مؤقت Cloudflare |
| البناء والتحديث | مثبتات وتحديثات موقعة وفحوص المستودع | GitHub Actions، مفاتيح التوقيع وأصول إصدار خالية من الكريدينشلز |

كل موصل منصة يقدم وظائف واضحة: اكتشاف الحسابات والقدرات، التحقق من المحتوى، الإرسال، وقراءة النتيجة. لا يتخذ الموصل قرارات تخالف خطة النشر التي وافق عليها المستخدم.

## 5. الإعداد ومساحات العمل

يبدأ مستخدم جديد بمساعد إعداد عربي. يدخل بيانات Cloudflare، ثم حسابات النشر وTelegram وHealthchecks بحسب ما يريد تفعيله. ينشئ التطبيق الموارد اللازمة في حسابه، ويربط الخدمة، ويفحصها. يمكن إضافة بيانات الموفر أو استبدالها لاحقًا من الإعدادات.

يشمل فحص الجاهزية الاتصال والصلاحيات، الموارد والربط بينها، الوصول إلى الوسائط، القنوات المدعومة، والمنصات غير المتاحة. تظهر نتيجة قصيرة لكل بند مع إجراء إصلاح محدد. لا يكفي وجود رمز أو استجابة HTTP ناجحة لادعاء جاهزية النشر.

ربط Facebook المباشر يستهدف الصفحات التي يديرها المستخدم، وربط Instagram عبر Facebook Login يستهدف حسابًا احترافيًا مرتبطًا بصفحة وصلاحياته المطلوبة. تظهر متطلبات نوع الحساب وصلاحياته قبل حفظ الربط. لا يعد رمز Facebook وحده ربطًا مستقلًا صالحًا لـThreads؛ الموفر الحالي المعتمد لـThreads هو Buffer.

تتضمن مساحة العمل الاسم، والمنطقة الزمنية، وإعدادات المنصات الافتراضية، والقنوات وموفريها، ومراجع الكريدينشلز، وإعدادات التقارير. يمكن لمساحتين استخدام نفس خدمة Cloudflare أو خدمتين مختلفتين. جميع العمليات والملفات والنتائج تتحقق من هوية المساحة، ولا تنتقل حسابات مساحة إلى أخرى بمجرد تبديل صندوق الاختيار.

تحفظ المسودة عند تبديل المساحة، ثم تعرض مسودة المساحة المختارة. تحتفظ كل نافذة بمساحتها ومسودتها. يعرض الإعداد الشخصي الأول حسابي Buffer الحاليين مع القنوات الصحيحة دون مطالبة صاحب المشروع بإعادة إدخال الرموز الموجودة.

## 6. صفحات الواجهة وإمكانية الوصول

الصفحات الأساسية: «منشور جديد»، «المجدولة»، «ملخص»، و«الإعدادات». صندوق اختيار مساحة العمل متاح في أعلى الصفحة. اللغة `ar` والاتجاه RTL، مع عرض الروابط والأسماء التقنية باتجاه مناسب داخل النص العربي.

تستخدم الواجهة العناوين والتسميات وحقول الإدخال والأزرار ومربعات الاختيار الأصلية. لا توجد عناصر تفاعلية بلا اسم، أو وظائف تتطلب الفأرة، أو دلالات تعتمد على اللون وحده. يظهر مؤشر التركيز بوضوح، ويكون ترتيب Tab موافقًا لترتيب القراءة. يراعى التباين والتكبير وتقليل الحركة.

لا ينقل رفع الملف أو تحديث النتيجة التركيز تلقائيًا. لا يستخدم تقدم الرفع منطقة إعلان حي تنطق كل تغيير. تعرض معلومات الرفع نصيًا وبعنصر تقدم مسمى، ويمكن الوصول إليها بالكيبورد. رسائل الخطأ مرتبطة بالحقول. عند فتح مراجعة بطلب المستخدم يوضع التركيز في عنوانها، وعند الرجوع يعود إلى الزر الذي فتحها.

يفتح `Ctrl+Shift+N` نافذة جديدة. المسودات مستقلة، بينما سجل المجدولة والنتائج مشترك ضمن المساحة. إذا عدلت نافذتان نفس المنشور، يمنع رقم الإصدار الكتابة فوق تعديل أحدث ويظهر تعارض مفهوم دون تغيير التركيز تلقائيًا.

## 7. إنشاء المنشور وتجهيز الوسائط

يمكن كتابة نص فقط، أو اختيار صورة أو مجموعة صور، أو فيديو واحد. لا تجمع هذه النسخة بين الصور والفيديو في منشور واحد، ولا تدعم رفع عدة فيديوهات دفعة واحدة. تخصيص كل منصة يقتصر على النص وأجزاء السلسلة والنص البديل؛ اختيار الوسائط مشترك، والنسخ المختلفة تنتج تلقائيًا حسب متطلبات المنصة.

عند اختيار ملف يبدأ فحصه ورفع الأصل في الخلفية، بالتوازي مع كتابة التفاصيل. تعرض النسبة والحجم المنقول والوقت المنقضي والتقدير المتبقي. إذا لم يمكن حساب الزمن المتبقي يعرض ذلك بوضوح بدل رقم مضلل. يمكن إلغاء الرفع وإزالة الملف. تستكمل الأجزاء المفقودة بعد انقطاع الشبكة، ولا يعاد رفع الأجزاء المكتملة بلا ضرورة.

اختيار الصور المتعددة يسمح بترتيبها وإزالة أي صورة. يحفظ اسم كل صورة الأصلي في بيانات الأصل ورابط الإرسال وترويسة اسم الملف. لا يغير التطبيق الملف المصدر. نسخة Instagram المحولة تحتفظ بجذر الاسم مع امتدادها الحقيقي. الأسماء الداخلية التي تنشئها المنصات بعد الاستلام ليست تحت تحكم التطبيق.

اختيار فيديو يظهر العنوان والوصف. العنوان مطلوب حتى إن لم يكن YouTube محددًا. يجهز اسم الملف المرسل من العنوان بعد إزالة محارف اسم الملف غير الصالحة، مع الامتداد الصحيح؛ يبقى عنوان المنشور كما كتبه المستخدم. لا يعاد تسمية الملف المصدر على جهازه. لا يتطلب تغيير عنوان الإرسال إعادة رفع نفس البايتات.

يستخدم النص أو الوصف كقيمة افتراضية للنص البديل حيث تسمح المنصة والموفر، ويقص إلى حدها مع الحفاظ على Unicode، ويمكن تعديله. لا يزعم التطبيق إرسال نص بديل لمنصة أو نوع وسيط لا يدعمه.

## 8. سياسة التوافق والتحويل

القواعد مبنية على تقاطع قدرات المنصة، وقدرات الموفر، ونوع الحساب وخطته. لا يكفي أن تدعم المنصة ميزة في تطبيقها الأصلي. تستخدم مصادر رسمية وقواعد محلية بإصدار معلوم، ويظل تحقق الموفر النهائي ملزمًا. البيانات التجريبية في APIs لا تصبح الاعتماد الوحيد لميزة أساسية.

| المحتوى | سلوك التطبيق |
| --- | --- |
| نص فقط | يرسل إلى المنصات التي تدعم النص المستقل عبر الموفر؛ تستبعد بقية المنصات مع السبب |
| صور | يستخدم الأصل حيث يقبله الموفر؛ نسخة Instagram المتوافقة تنشأ محليًا عند الحاجة |
| فيديو | يجهز نسخًا محلية عند اختلاف الحد الزمني أو الصيغة أو الحجم؛ يستخدم الأصل إذا كان مناسبًا |
| نص أطول من الحد | يرسل أول جزء مناسب افتراضيًا، ويعرض الطول الأصلي والحد قبل التأكيد |
| فيديو أطول من الحد | يأخذ البداية إلى الحد المسموح، ويعرض المدة الأصلية والمرسلة |
| صور أكثر من العدد المقبول | يرسل أول الصور بترتيبها حتى الحد، ويذكر عدد الصور المستبعدة |
| صيغة أصل غير مقبولة خارج Instagram | يوضح الاستبعاد أو التحويل الذي يفرضه الموفر؛ لا يعد بالحفاظ على صيغة يرفضها API |

يستهدف تحويل الصورة أعلى جودة ممكنة ضمن قيود الملف والأبعاد ونسبة العرض. عند الحاجة لتعديل الأبعاد يفضل إضافة هوامش مناسبة بدل اقتطاع محتوى الصورة. للفيديو الأفقي المطلوب كـShort عمودي أو مربع، يحافظ على المشهد بإضافة هوامش عند الحاجة. تظهر تغييرات الإطار أو الصيغة أو الحجم في المراجعة. تغيير حجم فيديو حتى يلائم الحد يحدث محليًا وبأعلى جودة مناسبة، ولا تبدأ معالجة على Cloudflare.

القص النصي يحترم الحروف المركبة والإيموجي، ويطبق حساب الأحرف الخاص بالمنصة، بما فيه أوزان الروابط في X. لا يقسم رمزًا أو محرفًا في منتصفه. يمكن للمستخدم تعديل النص بدل قبول القص.

السلاسل خيار صريح لـX وThreads. يمكن كتابة الأجزاء وترتيبها أو تقسيم النص آليًا إلى أجزاء قابلة للمراجعة. تظهر عدد الأجزاء والحدود واستبعاد أي جزء قبل التأكيد. تحفظ سلسلة واحدة كوحدة عمل مترابطة، وتظهر حالة الأجزاء إذا وقع نجاح جزئي. حدود Buffer المجانية تظل مطبقة؛ لا تعرض سلسلة على أنها مدعومة قبل التحقق من حد الحساب الفعلي، ولا تتحول إلى منشورات مستقلة لتجاوز القيد.

## 9. مراجعة النشر والتأكيد

زر «نشر» أو «جدولة» يفتح مراجعة للمحتوى النهائي. تبدأ بجملة العدد والموعد، ثم الملاحظات المؤثرة فقط: قص النص أو الفيديو، التحويل، النص البديل المقصوص، نقص عدد الصور، السلاسل، والاستبعادات وأسبابها. تتيح «تأكيد النشر» أو «تأكيد الجدولة» و«العودة للتعديل».

مثال: «سيُنشر على 4 منصات. فيديو X: أول 140 ثانية من 5 دقائق. Instagram: نسخة JPEG متوافقة. استُبعد YouTube لأن المنشور صور».

الخطة المؤكدة تربط النص والعنوان والمنصات والموفر والقنوات وأجزاء السلاسل والوسائط والتحويلات والموعد وإصدارات القواعد والإعدادات. أي تعديل مؤثر يبطلها ويحتاج مراجعة جديدة. يتيح عرض المراجعة أثناء الرفع، لكن زر التأكيد ينتظر اكتمال الملفات اللازمة. لا تنشر الملفات المرفوعة قبل التأكيد.

إذا تغيرت صلاحيات قناة أو حدود الموفر بعد التأكيد، لا ينفذ التطبيق تغييرًا جديدًا خفيًا في المحتوى. يسجل فشلًا أو حالة تحتاج تعديلًا مع السبب؛ لا يختار حسابًا مختلفًا تلقائيًا.

## 10. رفع واحد وروابط الوسائط

تستخدم الملفات الصغيرة رفعًا مباشرًا إلى R2 برابط رفع مؤقت. تستخدم الملفات الكبيرة رفعًا مجزأً قابلًا للاستكمال بأجزاء ثابتة، مع تزامن محدود، وإعادة محاولة للأجزاء الفاشلة. تبقى بيانات R2 السرية خارج واجهة الويب؛ يصدر Worker صلاحيات رفع قصيرة ومحدودة للملف والمساحة.

تعرف كل نسخة بالبصمة ومواصفات التحويل. المنصات التي تستخدم نفس النسخة تتشاركها. الصورة الأصلية ونسخة JPEG والفيديو المقصوص ملفات مختلفة فعلًا، وكل منها يرفع مرة واحدة. تعني «الرفع مرة واحدة» عدم تكرار الرفع لكل منصة، وليست منع إرسال بايتات نتيجة تحويل محلي مطلوبة.

تكون الروابط تحت نطاق فرعي من `aimansour.com`، مثل `media.aimansour.com`، بعد التأكد من توفر الاسم. تستخدم معرفات عشوائية غير قابلة للتخمين ومسار اسم الملف الصحيح. تعمل دون شاشة دخول للموفر، وتدعم GET وHEAD وRange، والحجم ونوع MIME الصحيحين. لا تحمل الروابط رموز Meta أو Buffer أو Cloudflare.

يفصل معرف R2 الداخلي عن اسم الإرسال الظاهر؛ بذلك يمكن حفظ الاسم الأصلي للصورة وتغيير اسم الفيديو حسب عنوانه دون نسخ الملف في R2. تظل روابط الوسائط ثابتة ومتاحة طوال الجدولة والمعالجة وحتى التحقق من النشر، وليس حتى قبول Buffer الطلب فقط.

تنظف الملفات المرفوعة التي لا ترتبط بمنشور مؤكد بعد 24 ساعة. تحذف النسخ المكتملة بعد 48 ساعة من اكتمال جميع المستهلكين. تحتفظ النسخ المرتبطة بفشل مؤكد 7 أيام لإتاحة الإصلاح، ثم تظهر الحاجة لإعادة رفعها إن لزم. لا تحذف وسائط منشور مجدول أو نتيجة إرسال غير محسومة لمجرد مرور مدة؛ تنبه إلى استهلاكها وتتيح للمستخدم إلغاء العمل وتنظيفها.

## 11. الجدولة والتعديل والإلغاء

تفعيل مربع «جدولة» يظهر التاريخ والوقت. القيمة الافتراضية وقت إنشاء صفحة المنشور زائد 10 ساعات. لا تتغير أثناء الكتابة. إذا أصبحت في الماضي يطلب التطبيق وقتًا صالحًا. المنطقة الزمنية خاصية المساحة، وافتراضيًا `Africa/Cairo`؛ تحفظ اللحظة الفعلية في UTC وتعرض محليًا مع مراعاة التوقيت الصيفي.

يحفظ تأكيد الجدولة سجلًا ثابتًا في D1 وينشئ Workflow مرتبطًا بالمنشور وإصداره. ينتظر Workflow الموعد على Cloudflare، ثم يعيد فحص الحالة قبل الإرسال. لا يحتاج الكمبيوتر إلى البقاء مفتوحًا بعد اكتمال الرفع وتأكيد الجدولة. المواعيد التي تتجاوز حد انتظار Workflow الموثق ترفض برسالة محددة.

التعديل أو الإلغاء يستخدم انتقال حالة ذريًا ورقم إصدار. Workflow قديم يستيقظ ثم يجد نفسه ملغيًا أو مستبدلًا، فلا يرسل المحتوى القديم. يستبدل تعديل الجدول العمل القديم بعمل للإصدار الجديد. تغيير الوسائط يتطلب جهازًا يكمل تجهيزها ورفعها قبل اعتماد التعديل.

عند بدء الإرسال يقفل التعديل والإلغاء لهذا الإصدار. أي منصة لم يبدأ إرسالها يمكن إيقافها إن ثبت ذلك في السجل. الطلب الذي أرسل فعليًا لا يوعد المستخدم بإلغائه، ولا تتضمن هذه النسخة حذف منشورات منشورة من المنصات.

## 12. الاعتمادية وحالات النشر

تسجل الحالة على مستوى المنشور وكل منصة وجزء سلسلة: مسودة، تجهيز، مجدول، جاهز للإرسال، قيد الإرسال، مقبول لدى الموفر، منشور، فشل، ملغى، أو نتيجة غير محسومة. النجاح الكلي يعني تأكيد النشر على جميع الأهداف غير المستبعدة. قبول Buffer طلبًا لا يحسب كمنشور مكتمل.

توجد معرفات عمل ثابتة وقفل إرسال لكل وجهة وإصدار. تحفظ معرفات الموفر عند استلامها، وتتابع حالة النشر باستعلامات مجمعة. تمنع العملية الذرية نوافذ التطبيق وWorkflows المتزامنة من إرسال نفس الوجهة مرتين.

فشل طلب قبل الإرسال أو رفض معدل الطلبات يسمح بإعادة محاولة مؤجلة وفق الحالة. إذا انقطع الاتصال بعد احتمال قبول كتابة لدى API لا يعاد إرسالها عميانيًا. تطابق الخدمة السجل مع الموفر حيث أمكن، وإلا تظهر «نتيجة غير محسومة» وتطلب إجراء واضحًا قبل إعادة الإرسال. لا يوجد وعد بإرسال مرة واحدة قطعًا حين لا يوفر API مفتاح منع تكرار أو وسيلة حسم موثوقة.

نجاح منصة وفشل أخرى لا يعيدان نشر المنصة الناجحة. إعادة المحاولة تستهدف الفشل القابل للإعادة فقط. تستخدم إعادة المحاولة تأخيرًا متزايدًا وعشوائية صغيرة وتحترم `Retry-After`؛ انتهاء صلاحية رمز أو محتوى غير صالح يحتاج إصلاحًا بدل إعادة محاولة مستمرة.

المتابعة الأولية لحالة منشورات Buffer بعد نحو دقيقة، ثم 5 و15 دقيقة، ثم فحص مجمع أقل تكرارًا حسب عمر العمل والحصة المتبقية. لا يتوقف التحقق من النتائج عند استنفاد محاولات سريعة؛ تبقى الحالة معلقة ويعمل الفحص المؤجل. يحد رصد التأخر من الأعمال التي توقفت عن التقدم، مع تمييز الانتظار المبرر من العطل.

## 13. التوفير والموارد

حدود Buffer الحالية لكل حساب مجاني: 100 طلب خلال 15 دقيقة، و250 خلال 24 ساعة، و3,000 خلال 30 يومًا، في نوافذ متحركة. الحسابان ميزانيتان مستقلتان؛ لا يمكن استعمال حصة حساب لقناة لا ترتبط به. الرقم 6,000 إجمالي نظري خلال 30 يومًا، وليس رصيدًا مشتركًا.

تجمع الطلبات المتوافقة في وثيقة GraphQL واحدة لكل حساب ضمن حد aliases والتعقيد، وتطلب الحقول اللازمة فقط. تعالج نتائج العمليات الجزئية بصورة مستقلة. تخزن القنوات والإعدادات مؤقتًا، ولا تستعلم من Buffer عند فتح كل صفحة أو نافذة. توجد عملية تحقق واحدة مشتركة ضمن الخدمة بدل تكرارها من الأجهزة.

تقرأ حصة الطلبات من الردود الفعلية وتحفظها. تقدم عمليات النشر على تحديثات غير ضرورية، وتحجز هامشًا للمتابعة والإصلاح. عند توقع نفاد الحصة تعرض تأخيرًا مفهومًا أو تمنع اعتماد موعد غير قابل للتنفيذ. لا تدور الرموز أو الحسابات لتجاوز القيود، ولا تدخل تحليلات Buffer التجريبية في ملخص الاستخدام.

تراقب حصة Cloudflare المشتركة بين Workers وWorkflows، وخطوات Workflow والتخزين وD1. الحد المنشور حاليًا لخطوات Workflows المجانية 3,000 يوميًا، وزمن CPU للخطوة 10 ms؛ تبقى الخطوات صغيرة وملفات الوسائط في R2، وتختبر حدود CPU في مسارات واقعية.

تحدد الخدمة سقفًا محافظًا مبدئيًا 9 GB من الملفات النشطة الخاصة بالمشروع، يشمل ما يستضيفه من ملفات إصدار. يحجز حجم الرفع المتوقع قبل إصدار صلاحية الرفع لمنع تجاوز السقف عبر نوافذ متزامنة. تظل حصة R2 المجانية 10 GB-month مشتركة مع بقية استخدام الحساب؛ سقف المشروع لا يضمن مجانية موارد أخرى في الحساب أو استهلاك سابق. يظهر الاستهلاك والتنظيف، ويمنع الرفع الجديد عند عدم توفر السعة المحجوزة.

## 14. الملخص وTelegram وHealthchecks

يعرض «ملخص» عدد المنشورات المنطقية المكتملة اليوم، والنجاح الجزئي والفشل والنتائج غير المحسومة، وعدد المجدولة القادمة. تعرض تفاصيل عدد الوجهات المنشورة أيضًا حتى لا يختلط منشور واحد على ست منصات بستة منشورات مستقلة. الأرقام مبنية على سجل الخدمة، وليست إحصاءات مشاهدات أو تفاعل.

النشاط اليومي يعني تأكيد نشر أو جدولة أو تعديل أو إلغاء منشور، أو حدوث نشر/فشل/تأخر يحتاج إجراء خلال اليوم. فتح التطبيق وحده ليس نشاطًا يوجب ملخصًا. عند منتصف الليل بحسب منطقة المساحة يرسل ملخص اليوم المنتهي مرة واحدة، إذا وجد نشاط. تظهر المنطقة والتاريخ في التقرير. يسجل التقرير بمفتاح فريد للمساحة والتاريخ، وقفل إرسال ومعرف رسالة Telegram عند وصوله. تسمح إعادة المحاولة عند ثبوت عدم الإرسال؛ نتيجة إرسال Telegram غير المحسومة لا يعاد إرسالها تلقائيًا بما قد يكرر التقرير.

رسالة مشكلة Telegram تتضمن المساحة، ومرجع المنشور والعنوان إن وجد، والمنصة، والخطوة، والسبب العربي، والوقت، وحالة إعادة المحاولة، والإجراء المطلوب. لا تتضمن الكريدينشلز أو كامل المحتوى والروابط السرية. يجمع التقرير النهائي المشكلات المتزامنة، وتبلغ المشكلات الدائمة فور اكتشافها؛ لا ترسل رسالة لكل محاولة عابرة. يرسل تحديثًا عند حسم حالة غير محسومة أو استعادة عطل مؤثر.

ينشئ Healthchecks فحصين لكل خدمة Cloudflare، وليس لكل منشور:

- نبض الخدمة كل 5 دقائق مع مهلة سماح 10 دقائق. ترسل نبضة النجاح بعد قراءة D1، وفحص وصول R2 بعنصر صغير، والتحقق من عدم وجود أعمال متأخرة بلا تقدم مبرر. لا يستدعي هذا الفحص Buffer أو Meta كل 5 دقائق.
- تقييم الملخص اليومي، بموعد يومي ومهلة 15 دقيقة. يستخدم منطقة مراقبة الخدمة، وافتراضيًا القاهرة، ويتحقق من استكمال تقييم مواعيد تقارير المساحات المستحقة حتى لحظة الفحص. يرسل إشارة بدء ثم نجاح عند اكتمال التقييم حتى لو لم يرسل Telegram بسبب غياب النشاط. يرسل `/fail` عند الفشل الصريح. تبقى تقارير كل مساحة مرتبطة بمنطقتها الزمنية، ويسجل تأخر أي منها ضمن فحص الخدمة.

يفحص مؤقت Worker الأحداث المستحقة مرة في الدقيقة باستخدام فهارس D1؛ يرسل نبض الخدمة كل خمس دقائق، ويتحقق من المواعيد اليومية، ويجري أعمال الصيانة المستحقة. يبقى التنفيذ الفعلي للمنشور في Workflows.

Healthchecks يكشف غياب النبضات بصورة مستقلة عن Cloudflare. تربط تنبيهاته بقناة Telegram تعمل خارج Worker، مع التحقق من وصول تنبيه فشل وتعافٍ. إن تطلب ربط التكامل دخول المستخدم أو خطوة في Telegram، توضح الخطوة عند الإعداد وتظل حالة القناة «تحتاج إكمال» حتى تختبر. قناة البريد الحالية متاحة كمسار إضافي. لا تعلن الجاهزية الكاملة للمراقبة قبل اختبار التنبيه الخارجي.

مفتاح إدارة Healthchecks يستخدم أثناء تجهيز الفحوص وتعديلها، ولا يحتاج Worker إلى الاحتفاظ به إذا كفت روابط النبضات. لا تؤدي مشكلة Healthchecks المؤقتة وحدها إلى إعادة نشر محتوى، وتعرض حالة المراقبة منفصلة عن نتائج المنصات.

## 15. حماية البيانات

تخزن بيانات الاتصال المحلية في خزنة نظام التشغيل. تحفظ إعدادات الخدمة ومساحات العمل غير السرية والمسودات في قاعدة محلية. تحفظ كريدينشلز النشر اللازمة للعمل أثناء إغلاق الكمبيوتر مشفرة في D1 بمفتاح خدمة داخل Worker Secrets. تظل بيانات إدارة Cloudflare في الخزنة المحلية أو أسرار CI المحدودة اللازمة للنشر.

توثق اتصالات التطبيق والخدمة بمفتاح جهاز قابل للإبطال، مع TLS، وصلاحيات تتأكد من المساحة وملكية الأصول في كل عملية. تحمل الواجهة مراجع الأسرار وحالتها، ولا تحصل على الرموز الخام من الخدمة. تقتصر أوامر Tauri على الملفات التي اختارها المستخدم والعمليات المطلوبة، مع سياسة CSP وصلاحيات محدودة؛ لا يوجد تنفيذ أوامر shell عام من الواجهة.

لا تظهر الرموز في السجلات ورسائل الخطأ وروابط الوسائط أو ملفات التثبيت أو المخرجات العامة. تنقح تقارير الأعطال والنسخ المصدرة. تحمى مفاتيح توقيع التحديث منفصلة عن بيانات النشر؛ تبقى بيانات المصدر الأصلية على الجهاز دون تعديل غير مطلوب.

## 16. البناء والصيانة والتحديث

يبني GitHub Actions مثبت Windows أولًا، مع مسار بناء ثانوي لـLinux وmacOS. تثبت إصدارات الأدوات والاعتمادات وActions بصورة قابلة للتكرار. تفحص الأنواع والاختبارات والبناء وتنسيق الكود، وتجرى مراجعات تبعيات وأمان بحسب ما تتيحه خطة المستودع الخاص.

تفتح تحديثات التبعيات طلبات تغيير قابلة للمراجعة، وتبنى وتختبر قبل إدخالها؛ لا ترقى الإصدارات الرئيسية آليًا بلا مراجعة. يصاحب كل إصدار وصف تغييرات عربي مختصر. يشمل توزيع FFmpeg إشعارات الترخيص ومعلومات المصدر اللازمة للبناء المستخدم.

توقع حزم Tauri Updater بمفتاح مخصص، وتتاح ملفات الإصدار والبيان عبر عنوان HTTPS يمكن للتطبيق الوصول إليه؛ لا يعتمد مستخدم التطبيق على تسجيل دخول إلى مستودع GitHub الخاص. توفر صفحة تنزيل/رابط مباشر للمثبت الخالي من بيانات الحسابات.

في الإعدادات زر «فحص التحديثات»، ثم تنزيل يظهر تقدمه، ثم تثبيت بطلب المستخدم. تتحقق المكتبة من التوقيع. لا يثبت التحديث أثناء رفع أو معالجة نشطة دون إنهائها أو إيقافها بصورة آمنة. تحفظ المساحات والمسودات، وتطبق ترحيلات البيانات بصورة قابلة للاستعادة. تحديث الخدمة السحابية لكل مستخدم يحافظ على بياناته ويتحقق من توافق إصدار التطبيق مع الخدمة، مع مسار لإصلاح أو ترقية الخدمة من الإعدادات.

## 17. حدود التنفيذ ومراحل التحقق

المكونات الأربعة في نطاق واحد مترابط: التطبيق المحلي، وخدمة النشر، والمراقبة، ومسار التوزيع. تقسم خطة التنفيذ إلى زيادات صغيرة قابلة للتحقق: هيكل قابل للبناء، إعداد وربط، دورة نشر كاملة، وسائط وجدولة، مراقبة وإدارة، ثم إصدار قابل للتنزيل. المراحل ليست حذفًا لمتطلبات التسليم.

يستخدم التنفيذ TDD للمنطق ذي المخاطر، ومراجعة الكود قبل دمج التغييرات الكبيرة، وأدلة تحقق فعلية قبل إعلان النجاح. لا تكتب اختبارات شكلية تعيد وصف الكود أو تختبر نصوص تنسيق منخفضة الأثر.

فحوص القراءة والتجهيز لا تنشر محتوى تجريبيًا على حسابات المستخدم. اختبارات النشر الحقيقية تمر بمحتوى مراجَع وتأكيد نشر من المستخدم، وتثبت النتيجة لكل منصة وروابطها حيث تتاح. تختبر بقية حالات الأعطال بموفرات محاكاة وبيئة محلية.

## 18. معايير القبول الملزمة

- [ ] يمكن تنزيل مثبت Windows خالٍ من الكريدينشلز وتشغيله على نظام نظيف، مع المتطلبات المحلية اللازمة.
- [ ] الإعداد الشخصي يستخدم الكريدينشلز الحالية بأمان، ويجهز موارد Cloudflare ويظهر نتائج الجاهزية الفعلية.
- [ ] مستخدم جديد يربط حساباته وخدمة Cloudflare الخاصة به، ويمكن إصلاح إعداد ناقص من الواجهة.

- [ ] يمكن كتابة نص، وتحديد الوجهات الافتراضية أو تغييرها، وتخصيص النص لكل منصة ومراجعة القص والاستبعاد.

- [ ] يبدأ الرفع عند الاختيار، ويعرض تقدمًا مفهومًا، ويتعامل مع الانقطاع والاستكمال وإلغاء الملفات والتنظيف.

- [ ] يمنع تعديل أو إلغاء ناجح إرسال الإصدار القديم؛ تختبر منافسة الموعد مع التعديل ونوافذ متعددة.
- [ ] لا تعيد نجاح منصة بسبب فشل أخرى، ولا تعيد كتابة نتيجة غير محسومة دون إجراء حسم.
- [ ] تعمل حدود الطلبات والانتظار المؤجل والتجميع والميزانيات وسقف الملفات تحت تزامن فعلي.
- [ ] تعرض صفحة الملخص أرقامًا صحيحة للمنشورات والوجهات والجدولة والفشل والحالات المعلقة.
- [ ] يصل تقرير مشكلة Telegram مفيد، وملخص منتصف الليل عند النشاط فقط، دون تكرار محاولات عابرة.
- [ ] يثبت اختبار Healthchecks اكتشاف توقف النبضات والفشل الصريح والتعافي ووصول التنبيه الخارجي.
- [ ] تنتج CI ملفات إصدار وتحديثات موقعة، وينجح فحص التحديث وتنزيله والتحقق منه وتثبيته مع حفظ البيانات.
- [ ] تجتاز الواجهة فحوص الكيبورد والدلالات والتباين، ثم ينجح اختبار المستخدم النهائي بواسطة NVDA أو تصلح ملاحظاته قبل التسليم.
- [ ] تسلم تعليمات عربية مختصرة للتثبيت والربط والاستعادة والاستخدام وحدود الخطط، مع دليل تحقق للإصدار.

## 20. نتيجة مراجعة المواصفات

راجعت الوثيقة مقابل المتطلبات والقرارات المعتمدة: فصل الرفع عن تأكيد النشر، والتمييز بين الأصل ونسخ المعالجة، وعدم حذف ملفات معلقة أو مجدولة، وحدود الإلغاء بعد بدء الإرسال، والتوقيت المحلي، وحماية بيانات المساحات، والتوزيع من مستودع خاص، والتنبيه المستقل عند توقف Cloudflare.

شروط الجاهزية التي تحتاج اختبارًا أثناء التنفيذ محددة بمعايير قبول، خاصة صلاحيات فيديو Meta وحدود سلاسل Buffer وربط Telegram داخل Healthchecks. لا تعرض هذه الحالات للمستخدم كقدرات متحققة قبل وجود دليل فعلي.

الخطوة التالية بعد مراجعة المستخدم لهذه الوثيقة هي كتابة خطة التنفيذ، ثم مراجعتها واختيار طريقة التنفيذ وفق Superpowers. لم تبدأ هذه الوثيقة تنفيذ كود المنتج أو إنشاء موارد خارجية.
